The engine becomes interactive. Input events flow from the platform through to the ECS. Sounds play.

## Scope

Input crosses three boundaries and belongs to none of them alone. `liara-platform` reports physical device state and physical events, and knows nothing about what an action is. The launcher maps a physical input to a logical action. `liara-core` carries the resulting events on its event bus, where systems consume them. Keyboard, mouse and one gamepad through SDL3's gamepad API are the first devices supported.

The mapping layer binds a logical action ("jump", "move_forward") to a physical input, meaning a key code, a mouse button, or a gamepad button or axis. Mappings live in TOML and can be changed at run time.

Audio goes through miniaudio, in the `liara-audio` module this version creates. WAV and OGG load and play. Initial scope is simple 2D sound with no spatialisation, per-source volume, and looping, with a configurable ceiling of simultaneous sources somewhere around 8 or 16.

The demo scene becomes interactive: WASD moves the camera, the mouse looks around, a sound plays on Space. It is not a game, and every primitive a game needs is now present.

## Developer tools

Two panels, one per new subsystem.

The input visualizer shows the live state of every device, meaning which keys are down, the mouse position and buttons, the gamepad axes and buttons. Below that it shows the resolved logical actions, which is the half that matters when a mapping is wrong.

The audio panel lists active sources with volume, playback position and loop state, allows pausing and stopping them, and keeps recently finished sources visible for a few seconds, which is what makes a timing problem diagnosable.

The settings inspector from v0.2 gains a category for input mappings, so bindings can be changed through the interface rather than by editing TOML by hand.

## Out of scope

3D audio, meaning spatialisation, attenuation and doppler (v1.x). More than one gamepad, deferred. Touch and VR input, out of scope. Mixing buses (v1.x).

## Definition of Done

- [ ] Keyboard, mouse and gamepad input reach the engine.
- [ ] Logical actions can be bound to physical inputs through configuration.
- [ ] WAV and OGG files play.
- [ ] The demo scene is interactive: the camera moves and an action produces a sound.
- [ ] The input visualizer shows physical state and resolved actions.
- [ ] The audio panel lists active sources and can pause and stop them.
- [ ] Mappings can be edited at run time through the settings inspector.
- [ ] The user documentation has "Handling input" and "Playing sounds".
- [ ] `liara-audio` exists, is released, and appears in the compatibility record.
