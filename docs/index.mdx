Liara is a 3D game engine built as a set of independently versioned modules talking to each other through a C ABI. These pages are the engine's own documentation: the reasoning, the repository map, the mechanics and the process.

## Reading it another way

If you are here for one thing rather than for the whole picture, three entry points are faster than the order above.

**To get something running**, go to [Bootstrap](./bootstrap/) and skip everything else until it builds. The architecture reads better once you have seen the thing compile.

**To find out where something lives**, [Where things live](./modules/cross-reference/) is a topic-to-repository table, and it is the fastest answer to "which repository owns this".

**To understand why a decision looks the way it does**, go to the [decision record](./adr/) before the page describing it. The pages state what is true, and the records state what else was considered and why it lost, which is usually the part that actually answers the question.

## A note on what is true today

The engine is in v0.1, with Phase 0 closed behind it, and most of what these pages describe is designed and not yet built. That is stated page by page rather than hidden behind a disclaimer: where something is planned, it says so, and where the code currently contradicts a stated principle, there is a note saying which one wins and when.

The parts that are real today are the contract, the two placeholder modules, the launcher that composes them, and the infrastructure around all of it. [Roadmap](./roadmap/) is the honest account of the rest.
