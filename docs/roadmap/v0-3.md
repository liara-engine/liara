Persistent assets: meshes from glTF files, textures from PNG and JPG, shaders compiled from GLSL to SPIR-V at build time. This version creates `liara-assets`.

## Scope

Loading, decoding and lifetime management of assets belong to `liara-assets` from the outset rather than being extracted from the core later. An asset system that starts inside the core acquires a dozen callers before anyone notices, and the extraction stops being a move and becomes a rewrite. [ADR 0004](../adr/0004-module-boundaries/) is that argument in general form, and this is where it gets applied.

The module exposes `liara_assets_load_mesh`, `liara_assets_load_texture` and their release counterparts across the ABI, in its own namespace. The core does not call them and does not link against the module. The launcher composes the two, as it does for every other pair.

glTF 2.0 is the mesh format and PNG the texture format, decoded through cgltf or tinygltf, undecided, and stb. Neither library appears in a public header: they are implementation details, and the ABI exposes handles.

Static meshes only, with embedded or external textures. glTF materials are read and only `baseColorTexture` is honored at this stage. Texture loading goes through stb_image, supports PNG and JPG, and generates mipmaps automatically.

The launcher's procedural cubes give way to real glTF assets loaded from disk, with a small selection of test assets shipping alongside: a textured cube, a Suzanne head, a simple environment.

Shader hot-reload arrives in development builds: the engine watches the shader sources and reloads pipelines when they change. It is a quality-of-life feature for building the engine rather than a shipped capability.

## Developer tools

The asset browser: a panel listing every loaded asset by type, with its path, reference count, memory footprint and load timestamp. It is the primary tool for diagnosing asset lifetime problems during development, meaning leaked references, accidental reloads and unexpected eviction.

A small preview capability goes with it, so that clicking a mesh or a texture shows it, which is how you find out the loaded asset is not the one you meant.

## Out of scope

Several textures per mesh, which comes with materials in v0.4. glTF skeletal animation, deferred indefinitely or to v1.x. KTX2 compressed textures (v1.x). An asset preprocessing pipeline (v2.x). Asynchronous loading, since v0.x loads synchronously and async arrives when something needs it.

## Definition of Done

- [ ] glTF static meshes load correctly.
- [ ] PNG and JPG textures load with mipmaps.
- [ ] Shader hot-reload works in development builds.
- [ ] Reference counting is correct, verified by tests.
- [ ] The asset browser shows type, reference count, memory footprint and a preview for meshes and textures.
- [ ] The demo scene loads three different glTF models with textures.
- [ ] The user documentation has "Loading your first asset".
- [ ] `liara-assets` exists, is released, and appears in the compatibility record.
