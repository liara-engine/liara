With the modular pipeline proven, this version introduces the data model. The ECS becomes real, the math types appear in the headers, and the render packet pattern gets exercised for the first time.

## Scope

The core implements the ECS: entity allocation with generational handles, sparse-set component storage, a query API iterating over a component set, and the entity lifecycle of create, destroy and batch destroy.

The math types in `liara-interfaces` are populated: `liara_vec2_t`, `liara_vec3_t`, `liara_vec4_t`, `liara_mat3_t`, `liara_mat4_t`, `liara_quat_t` and `liara_transform_t`, with the core implementing the operations on them. `liara_transform_t` is where the double-precision translation decided in [Cross-platform strategy](../../architecture/cross-platform/) actually lands.

The render packet is finalized for v0.x: views, drawables and lights, the last as placeholders. The core builds one each tick from ECS state and the renderer consumes it. That replaces the grid of colored cells the Phase 0 packet carries today.

The launcher's hardcoded triangle gives way to a few entities carrying a transform and a mesh renderer, the mesh being a procedurally generated cube, with a camera entity providing the view. What you see is several cubes and a camera rotating around them.

## Developer tools

The first ones arrive here, because v0.2 is the first version producing data worth looking at.

The renderer integrates ImGui, prepared during v0.1 and exercised here. A stats overlay shows FPS, frame time and entity count. A log console consumes the logger's in-memory ring buffer and displays entries live, filtered by level and by source. A settings inspector lists the registered settings, shows their values and allows changing them at run time.

That establishes the pattern every later subsystem follows: the tools that make a feature observable ship in the same version as the feature.

## Performance

A benchmark joins `liara-core`'s suite: instantiate 10,000 entities with a transform and a mesh renderer, iterate over them, report microseconds per iteration. It runs in CI and its result is recorded. The number does not gate the milestone. Its existence does.

## Out of scope

Loading meshes or textures from files (v0.3). Materials beyond a hardcoded color and lighting computation (v0.4). An ECS scheduler running systems in parallel, deferred until something measurable needs it. Component relations, observers and prefabs, deferred to v1.x.

## Definition of Done

- [ ] The ECS is implemented in `liara-core`, with tests covering entity creation and destruction, generation counters, component add and remove, and queries.
- [ ] The math types and their operations are implemented and tested.
- [ ] The render packet structures are defined in `liara-interfaces`.
- [ ] The core builds a packet from ECS state each tick.
- [ ] The renderer consumes it and draws the entities.
- [ ] Several cubes appear at distinct positions.
- [ ] A camera rotates around them.
- [ ] The ECS benchmark runs in CI and its results are recorded.
- [ ] The stats overlay shows FPS, frame time and entity count.
- [ ] The log console shows logger output live, filtered by level and source.
- [ ] The settings inspector lists the registered settings and allows changing them.
- [ ] The user documentation has a "Hello ECS" tutorial.
