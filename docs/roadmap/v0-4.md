The first non-trivial rendering. Lighting calculations, several texture slots, basic materials. The scene starts looking like a scene.

## Scope

The renderer implements forward rendering with Blinn-Phong lighting. One directional light, several point lights with a hardcoded ceiling around 32. Lighting parameters cross in the render packet through a `liara_light_t`.

A material system replaces v0.3's hardcoded color. Each mesh references a material, and a material has an albedo texture, a normal map and an optional metallic-roughness map used as one greyscale combined map. This is not PBR. It is Blinn-Phong parameterized by textures, and calling it what it is now avoids explaining later why it does not look like PBR.

Transparency arrives in a basic form: a material declares itself `OPAQUE` or `BLEND`, and blended materials are sorted back to front. Alpha cutout works through a threshold.

The demo scene becomes a textured environment with several meshes, a directional light producing simple shading, and a few point lights with attenuation.

## Developer tools

The debug rendering subsystem arrives here. Lines, wireframes, axis-aligned and oriented bounding boxes and frustums can be submitted by any system through the debug primitives API in `liara-interfaces`, and are drawn in a dedicated pass after the main scene. This is the subsystem the editor later reuses for its gizmos, which is why it is a pass of its own rather than something bolted onto the main one.

Light sources gain visualization: a directional light draws its direction as an arrow, a point light draws its attenuation radius as a translucent sphere, and the active camera frustum can be overlaid, which is what you want when debugging culling. All of it toggles from the overlay.

The stats overlay gains a per-stage timing breakdown: CPU update, packet build, GPU submit, present. First appearance of profiling data, and a real profiler with a timeline view is deferred to v1.x.

A material inspector allows changing the active material's parameters at run time, which is how you tune lighting without recompiling.

## Out of scope

Shadow mapping, PBR, image-based lighting (all v1.x). Deferred rendering (v1.x or v2.x). Anti-aliasing beyond what Vulkan does by default. Post-processing.

## Definition of Done

- [ ] Materials with albedo, normal and combined metallic-roughness slots work.
- [ ] One directional light and several point lights render with correct shading.
- [ ] Blend and cutout transparency work.
- [ ] The demo scene is visually convincing.
- [ ] Debug primitives are submittable through the public interface and draw correctly.
- [ ] Light debug visualization works.
- [ ] The stats overlay shows the per-stage breakdown.
- [ ] The material inspector changes parameters at run time.
- [ ] The user documentation has "Lighting your scene".
