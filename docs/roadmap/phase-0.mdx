Phase 0 is not a version of the engine. It produced no engine code, and it produced an environment in which engine code can be productively written. It was treated as one atomic unit, complete only once every item below was in place.

**It is closed.** Every item below is met, and [v0.1](../v0-1/) is the version under way.

## The Phase 0 exemption

**This exemption has expired.** It ended when Phase 0 closed, and the processes it relaxed now apply in full. What follows is kept because it explains why the early history of every repository in the project looks the way it does, and it grants nothing today.

The processes described in [Contributing](../../contributing/), [Tooling](../../tooling/) and the [interface guide](https://liara-engine.liara-engine-documentation.workers.dev/liara-interfaces/latest/guides/) are target processes: they describe how the project operates once its infrastructure exists. During Phase 0 that infrastructure was the work, and subjecting its own construction to it would have been circular and needlessly heavy.

So until Phase 0 closed, four things were relaxed.

Replacing a planned tool with a better one found during implementation, or dropping one that turned out to be unrealistic, did not require a decision record. It required updating the document that described it.

The documents written before implementation were drafts rather than contracts. Where implementation and document disagreed, the implementation was presumed right and the document corrected, unless review concluded the opposite.

Interfaces, workflows, scripts and schemas could change shape without the version ceremony `INTERFACES.md` describes.

The decision records written at the end of Phase 0 record the decisions as they ended up, rather than the sequence of intermediate positions that produced them.

That is what the zero meant: nothing was fixed yet, and Phase 0 was where the plan met the tools and the tools sometimes won.

What the exemption never covered is the Definition of Done. Its items could be reworded as understanding improved, and they were not waived. The permissiveness was about how an item was reached, not about whether it was.

## Repositories <Badge text="Done" variant="success" />

Seven repositories exist under the `liara-engine` organization: `liara`, `liara-interfaces`, `liara-core`, `liara-renderer`, `docs-shared`, `liara-docs` and `.github`.

Each module repository carries a minimal stub: a `CMakeLists.txt` that compiles, a README pointing at the meta repository, a LICENSE, a `.gitignore`, an `.editorconfig`, a `.clang-format`, a `.clang-tidy`, and a placeholder test that passes.

`liara-editor` and `liara-physics` are deliberately not created. They arrive when their first line of code is written.

## Documentation <Badge text="Done" variant="success" />

The meta repository carries the architecture, modules, roadmap, contributing, code style, tooling and bootstrap documents, plus the decision records covering the decisions taken so far. `liara-interfaces` carries its own `INTERFACES.md`. `docs-shared` carries the Astro preset, the site tools, the hub and the builder image, along with its own guide to all of it.

## CI <Badge text="Done" variant="success" />

Each module repository has workflows that build on Linux under GCC and Clang and on Windows under MSVC, run clang-format and clang-tidy, run the test suite, generate the documentation, and deploy it on a push to `main`. The workflows that implement all of that live in `.github` and are called from each repository.

## Release automation <Badge text="Done" variant="success" />

Every repository has release-please configured against its conventional commits, with `release-please-config.json` and `.release-please-manifest.json` at its root.

## Workspace bootstrap <Badge text="Done" variant="success" />

`scripts/liara.py` clones each module repository into `workspace/`, generates the superbuild `CMakeLists.txt`, configures CMake through the presets, and produces the `compile_commands.json` clangd consumes.

Its success criterion: from a fresh clone of the meta repository on a machine meeting the prerequisites, `./scripts/liara.sh setup` produces a configured, buildable workspace with no manual intervention. The first run also resolves and builds the vcpkg dependencies, which dominates wall-clock time and is not part of the criterion. A warm re-run finishes in under five minutes.

## Documentation hub <Badge text="Done" variant="success" />

The hub displays a landing page with the project's name and description, and offers the version and module switchers.

The module pages it links to were allowed to be empty placeholders at that stage. What Phase 0 needed was for the navigation infrastructure to work.
